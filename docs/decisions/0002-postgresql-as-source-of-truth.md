# ADR 0002: PostgreSQL을 상태의 기준으로 사용

## 상태

초기 버전에 대해 승인함.

## 배경

재고, 인당 제한, 점유, 주문, 결제 확정은 동시 요청에서도 일관되게 변경되어야 합니다. PostgreSQL은 초기 비즈니스 흐름 전체에 영속적인 트랜잭션과 제약 조건을 제공할 수 있습니다. Redis나 메시지 큐를 먼저 추가하면 기준 구현의 병목을 확인하기 전에 또 다른 상태 소유자와 장애 경계가 생깁니다.

보관된 프로젝트에는 RDB와 Redis 비교 실험이 있지만 이전 구현에서 측정한 결과이므로 현재 계약의 요구를 증명하지는 않습니다.

## 결정

모든 비즈니스 상태의 기준을 PostgreSQL에 저장합니다. 최초 재고 점유 전략은 원자적 SQL과 트랜잭션 검사를 사용합니다. Redis, 메시지 브로커, 인메모리 값을 독립적인 재고 기준으로 사용하지 않습니다.

## 결과

- 하나의 트랜잭션 경계에서 정합성을 설명하고 테스트할 수 있다.
- 애플리케이션 검증에 더해 DB 제약 조건을 두 번째 방어선으로 사용할 수 있다.
- 순간 트래픽에서 PostgreSQL 연결 수나 hot row가 처리량을 제한할 수 있다.
- 이후 캐시나 진입 제어 계층을 추가하더라도 PostgreSQL이 최종 기준이라는 전제를 유지해야 한다.

## 재검토 조건

합리적인 SQL·인덱스·트랜잭션·연결 풀 조정 후에도 재현 가능한 부하 테스트에서 요구 지연시간, 처리량, 자원 목표를 달성하지 못하면 재검토합니다.
