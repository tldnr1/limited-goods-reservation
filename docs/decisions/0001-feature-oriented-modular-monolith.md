# ADR 0001: 기능 중심 모듈러 모놀리스

## 상태

초기 버전에 대해 승인함.

## 배경

핵심 문제는 인당 제한, 재고, 점유, 주문, 결제 상태를 하나의 연결된 트랜잭션으로 처리하는 것입니다. 프로젝트는 한 사람이 관리하고 컴퓨팅 자원이 제한되어 있으며, 특정 기능을 독립적으로 배포하거나 확장해야 한다는 근거가 아직 없습니다.

전역적인 Controller·Service·Repository 계층은 하나의 구매 유스케이스를 여러 기술 패키지에 흩어놓을 수 있습니다. 마이크로서비스는 측정된 문제를 해결하기 전에 분산 정합성, 네트워크, 배포, 관측성 비용을 추가합니다.

## 결정

하나의 Python 코드베이스를 비즈니스 기능 중심으로 구성합니다. `sales`, `purchases`, `reservations`, `payments` 모듈이 각자의 규칙과 저장 코드를 소유합니다. HTTP 처리와 백그라운드 작업은 필요하면 별도 프로세스로 실행하지만 같은 애플리케이션에서 배포합니다.

## 결과

- 구매 흐름을 하나의 PostgreSQL 트랜잭션 안에서 처리할 수 있다.
- 분산 시스템을 운영하지 않고도 모듈의 책임을 설계하고 테스트할 수 있다.
- 구현이 부주의하면 모듈 간 결합이 커질 수 있으므로 소유권과 의존 방향을 검토해야 한다.
- 프로세스 단위 확장은 가능하지만 모듈을 독립적으로 배포할 수는 없다.

## 재검토 조건

특정 모듈에 독립적인 확장, 장애 격리, 보안 경계, 팀 소유권, 배포 주기가 필요하다는 근거가 생기면 재검토합니다.
